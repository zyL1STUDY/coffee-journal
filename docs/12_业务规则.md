# 12 业务规则

## Coffee Record

- 一条 Coffee Record 只能有一种 `source_type`。
- `source_type` 必须是 `brand` / `cafe` / `homemade` 之一。
- `source_name` 根据 `source_type` 表示不同含义：
  - `brand`：品牌名。
  - `cafe`：咖啡店名。
  - `homemade`：制作方式。
- `drink_name` 可为空。
- `note` 可为空。
- `photo_url` 可为空。
- 用户不喜欢拍照或当下不方便拍照时，必须允许跳过照片。
- 删除使用软删除：设置 `is_deleted=true` 和 `deleted_at`，不直接物理删除。

## 保存与 AI

- 保存记录时，即使 AI 失败，也必须保存 Coffee Record。
- Coffee Memory 的 AI Message 在保存时生成并固定保存。
- Coffee Memory 打开时不重新实时生成 AI Message。
- Today Card 和 Journal Summary 可以使用默认文案兜底。
- AI 不做聊天机器人、心理咨询、健康诊断、摄入量建议或用户评价。

## Journal

- Journal 按 `created_at` 显示记录。
- Journal 默认过滤 `is_deleted=true` 的记录。
- 同一天多杯咖啡显示数量 Badge。
- 无记录日期只显示日期数字。
- 有记录日期显示日期数字和照片缩略图。
- Journal 不提供新增入口。

## Coffee Memory

- Coffee Memory 是回忆页，不是后台详情页。
- Coffee Memory 从 Journal 的记录入口打开。
- 删除 Coffee Memory 前必须二次确认。
- 删除成功后返回 Journal 并刷新数据。
- 编辑成功后返回 Coffee Memory 并刷新内容。

## Home

- Home 显示今天记录和最近咖啡。
- Home 是记录入口。
- 保存 Coffee Record 后返回 Home 并刷新最近咖啡。

## Profile

- Coming Soon 功能不可进入正式功能。
- Coming Soon 功能点击后可显示 Toast，或不响应。

## MVP 不做

- MVP 不做登录。
- MVP 不做社交。
- MVP 不做付费。
- MVP 不做复杂健康分析。
- MVP 不做 Apple Watch。
- MVP 不做桌面小组件正式实现。
- MVP 不做 Coffee Sticker 收藏正式实现。
