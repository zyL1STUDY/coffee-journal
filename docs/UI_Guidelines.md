# UI 规范

> 辅助文档 / 设计补充。
>
> 本文件保留早期 UI 原则和设计讨论。正式设计规范请以 `07_设计规范.md` 为主；如两者冲突，以 `07_设计规范.md` 和 Figma Final Screens 为准。

## 产品方向

Coffee Journal 始终按照移动端 App 设计。

整体气质应该是安静、温暖、极简、个人化。

## 移动端优先

- 默认预览尺寸：iPhone 15，390 x 844。
- 即使运行在 Chrome 中，App 也应该保持居中的手机预览框。
- 底部导航必须属于手机界面内部。
- 当前 MVP 不设计桌面布局。

## 主题

所有 UI 应优先使用集中式 Theme，不要随意硬编码视觉值。

当前色彩：

- Background: `#FFFDFB`
- Primary: `#F4D7D7`
- Accent: `#5A4636`

## 布局

- 使用舒适的移动端留白。
- 页面要聚焦、轻量、克制。
- 避免 Landing Page 风格。
- 当复用组件能减少重复并提高一致性时，优先使用复用组件。

## 导航

MVP 使用三个底部导航：

- 今天
- Journal
- 我的

Camera 不作为一级 Tab。拍照是记录流程里的动作，不是一个独立页面目的地。

## Figma 设计方向

当前 Figma 中有两个记录流程探索版本：

- V1 - 先记录：从来源和记录详情开始。
- V2 - 默认拍照优先：从捕捉咖啡时刻开始，同时允许用户跳过拍照。

当前优先方向是 V2。

## 记录流程原则

- 默认拍照优先，但随时可以跳过。
- 不要强迫用户在保存前填写很多字段。
- 使用同一个底部弹层内部切换步骤，不要连续叠加多个弹层。
- 底部弹层高度应该根据内容量变化：
  - 短内容使用短弹层。
  - 来源选择使用中等弹层。
  - 只有完整详情表单才使用高弹层。
- MVP 可见文案默认使用中文。
- 避免 Material Form 风格。记录流程应该像一张温暖的小记录卡。

## 来源路径

记录流程 V2 使用三个来源路径：

- 连锁品牌：先选择品牌，再补充可选饮品名。
- 独立咖啡店：先选择或创建咖啡店，再补充可选饮品名。
- 自己做：先选择制作方式，再补充可选饮品名。

饮品名应该是用户真实记得的名称，例如「红酒美式」或「生椰拿铁」。  
「美式」「拿铁」这类泛分类可以后续由系统推断，不应作为 MVP 的必填输入。

## Journal 设计原则

- Journal 是 Coffee Memory，不是普通日历。
- 月历应该是页面视觉中心。
- 保留用户熟悉的传统月历结构：月份、星期、日期。
- 有照片的日期使用圆形照片缩略图。
- 没有照片的日期只显示日期。
- 同一天多杯咖啡时，在照片右上角显示数量 Badge。
- 统计信息放在月历下方，保持小卡片和低视觉重量。
- AI 只保留一句 Summary，最多两行，不做大卡片。

## Coffee Detail 设计原则

- 点击 Journal 中的咖啡照片后，不跳转新页面。
- 使用背景变暗 / 模糊感 + Bottom Sheet。
- Bottom Sheet 与 Record Flow 保持一致的大圆角、柔和阴影和留白。
- 详情内容优先展示照片和记忆，再展示操作。
- 编辑和删除是操作入口，不应该抢占主要视觉中心。
